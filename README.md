# Aharon CRM — Pure Node.js CRM

מערכת CRM עצמאית ב־Node.js וב־Fastify, עם MySQL/MariaDB ישיר, ממשק בעברית ותיבת הודעות מאוחדת. הקוד ממשיך את המימוש הקיים במאגר.

## יכולות

- ניהול לקוחות, פרויקטים, משימות, מערכות וחשבונות, שיוכים והערות CRM, והעלאת קבצים פרטיים עד 25MB.
- Unified Inbox: הודעות Gmail, Hostinger Mail ו־WhatsApp באותה שכבת שיחות והודעות.
- Gmail: Google OAuth, ריבוי חשבונות, גוף הודעה מלא, היסטוריית השרשור, העתקים ותשובה בשרשור.
- Hostinger: IMAP לקבלה, SMTP לשליחה, TLS כברירת מחדל; שרשור לפי Message-ID ו־References.
- WhatsApp: Baileys, סריקת QR מתוך הממשק, קבלה ושליחה, חיבור מחדש וניתוק. קובצי החיבור נשמרים בתיקיית runtime בלבד.
- Google Calendar ו־Drive: קריאת אירועים וחיפוש מטא־נתונים דרך MCP.
- AI Draft Assistant: טיוטות שמבוססות על לקוח, שיחה, הודעות קודמות, פרויקטים, משימות, מערכות, הערות ופעילות. ההקשר מוגבל באורך ושומר עדיפות להודעה האחרונה. חיפוש מידע נוסף מוגבל לרשומות המשויכות כדי למנוע עירוב מידע של לקוחות אחרים.
- Smart Background Worker: תפיסה אטומית של משימות AI, תוצאה שמורה, פעילות ועדכון בזמן אמת. עד שלושה ניסיונות עם השהיה; משימה שנתקעה ניתנת לאיסוף מחדש לאחר 30 דקות.
- MCP מאומת, WebSocket עם כרטיס חיבור חד־פעמי, כניסה עם עוגייה חתומה ומוגבלת בזמן.

## Installation

Node.js **20.9 ומעלה**. הבדיקות עברו ב־Node.js 20.20.2 וב־24.19. לפריסה חדשה מומלץ להשתמש בגרסת Node הנתמכת אצל ספק האירוח.

```bash
npm ci
npm run check
npm test
npm run scan:secrets
npm start
```

`package-lock.json` נכלל במאגר. `.npmrc` מונע הורדה מיותרת של רכיבי CUDA; המודל רץ על המעבד. הגדר גם `ONNXRUNTIME_NODE_INSTALL_CUDA=skip` במשתני הסביבה של תהליך הבנייה ב־Hostinger. בפריסה חוזרת ניתן להשתמש ב־`npm ci`.

## Environment

כל השמות והערכים שאינם סודיים מופיעים ב־`.env.example`. הגדר את הערכים במשתני הסביבה ב־Hostinger; היישום אינו טוען קובץ `.env` אוטומטית.

חובה:

- `DB_HOST`, `DB_PORT`, `DB_NAME`, `DB_USER`, `DB_PASSWORD` — מסד MySQL 8+ או MariaDB 10.6+ התומך ב־`SKIP LOCKED`. משתמש המסד צריך הרשאות יצירת טבלאות ושינוי עמודות לצורך העדכונים האוטומטיים.
- `DASHBOARD_PASSWORD`, `SESSION_SECRET`, `CORE_API_TOKEN`, `MCP_API_TOKEN`, `CONNECTOR_VAULT_KEY`, `OAUTH_STATE_SECRET` — ערכים נפרדים ואקראיים, לפחות 32 תווים לכל ערך בסביבת production. החלפת מפתח הכספת מחייבת חיבור חשבונות Google מחדש.
- `PUBLIC_BASE_URL` — כתובת HTTPS של היישום.

חיבורים:

- Google: הגדר `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, `GOOGLE_REDIRECT_URI`; הפעל Gmail API, Calendar API ו־Drive API בפרויקט Google. כתובת ההחזרה היא `/oauth/google/callback`. חיבור החשבון נעשה ממסך החיבורים. חשבון שכבר מחובר עשוי להצריך חיבור חוזר לאחר שינוי הרשאות.
- Hostinger: חיבור באמצעות כתובת דואר וסיסמה במסך החיבורים, אחרי בדיקת IMAP ו־SMTP ושמירה מוצפנת; לחלופין `HOSTINGER_MAIL_ENABLED=true`, `HOSTINGER_MAIL_USER`, `HOSTINGER_MAIL_PASSWORD`. ברירות המחדל הן `imap.hostinger.com:993` ו־`smtp.hostinger.com:465`, עם TLS. נתמך חשבון Hostinger אחד לכל פריסה.
- WhatsApp: `WHATSAPP_ENABLED=true`, ואז סריקת QR ממסך החיבורים. Baileys הוא חיבור לא רשמי; תקינותו תלויה בשירות WhatsApp.
- AI מקומי: `LOCAL_AI_ENABLED=true`, מודל `onnx-community/Qwen2.5-0.5B-Instruct`, כימות `q4`. המשקולות מורדות בפעם הראשונה ל־`runtime/huggingface`. אין משקולות במאגר.
- ספק AI חיצוני, אופציונלי: `AI_BASE_URL`, `AI_API_TOKEN`, `AI_MODEL`. ניתן לבחור ספק ראשי וגיבוי במסך ההגדרות. אם הוגדר, ההקשר שנאסף מועבר לספק החיצוני.

המודל הקטן אינו מבטיח דיוק בעברית או היעדר המצאות; יש לקרוא ולערוך כל טיוטה. הוא לא שולח הודעות. ההורדה והטעינה הראשונות דורשות רשת, נפח דיסק וזיכרון פנוי; יש לבדוק את מכסת תהליך ה־Node בחבילת Hostinger בפועל.

## Deployment

- Startup: `npm start`.
- Entry: `app.cjs`.
- Fastify מאזין ל־`HOST` ול־`PORT`. החיבור למסד ועדכוני המבנה מתבצעים לפני פתיחת השרת.
- ודא שתיקיית `runtime` ניתנת לכתיבה ונשמרת בין פריסות; היא מכילה כספת Google מוצפנת, חיבור WhatsApp ומטמון מודל.
- יש להריץ מופע אחד לכל תיקיית runtime. הכספת וקובצי WhatsApp אינם מיועדים לכתיבה משותפת ממספר תהליכים.
- `/health` מחזיר מצב חיות בסיסי ללא נתוני לקוחות או QR. `/api/*` דורש התחברות; `/v1/*` מקבל גם `CORE_API_TOKEN` בכותרת Bearer.

## תפעול והודעות

במסך החיבורים מחברים חשבונות. הודעות נכנסות עוברות עיבוד ברקע וטיוטה מוכנה מופיעה בשיחה. אפשר לערוך, לדחות, ליצור מחדש ולאשר שליחה. מסך העוזר מבצע חיפוש ושימוש בכלים לפי ההרשאות והמדיניות השמורה.

סנכרון הדואר הוא מחזורי: Gmail בוחר הודעות לפי `GOOGLE_SYNC_QUERY` והגבלת `GOOGLE_SYNC_MAX_RESULTS` וטוען את כל ההודעות בשרשורים שנבחרו; Hostinger קורא עד 200 הודעות אחרונות בתקופת `HOSTINGER_MAIL_SYNC_DAYS`. זה אינו ייבוא מלא של תיבה גדולה. סימון נקרא בממשק הוא מקומי; הוא אינו משנה דגלי קריאה אצל ספק הדואר. קובצי מדיה מצורפים אינם מיובאים כחלק מגוף ההודעה.

שליחה מקבלת `request_id` ייחודי. במקרה של תוצאת שליחה לא ודאית, אין ניסיון אוטומטי חוזר: יש לבדוק בתיבת הספק לפני שליחה חדשה כדי להימנע מכפל הודעות. Worker יוצר תוצאה בלבד גם במצב `ai`.

## MCP

כתובת: `/mcp`, שיטת POST ו־Streamable HTTP. יש לשלוח `Authorization: Bearer <MCP_API_TOKEN>` ולקבל `application/json, text/event-stream`.

ברירת מחדל: מצב מערכת, חיפוש CRM, רשימות וקבלת פרויקטים/לקוחות/מערכות/משימות/שיחות, פעילות, חיבורים, Calendar ו־Drive, ויצירת טיוטה שאינה נשלחת.

- `MCP_ALLOW_WRITES=true`: יצירה ועדכון של משימות ולקוחות.
- `MCP_ALLOW_SENSITIVE_WRITES=true`: `send_email` ו־`send_whatsapp` לשיחה קיימת בלבד, עם `confirm=true` ומזהה בקשה. ברירת המחדל כבויה.

## נעילת כניסה והגנת IP

מסך הכניסה מציג רק את המוצר Aharon CRM וכולל כפתור הצגה/הסתרה של הסיסמה באמצעות Bootstrap Icons. ברירת המחדל היא שלושה ניסיונות כניסה שגויים מאותה כתובת IP. בניסיון השלישי המערכת:

- מוסיפה את ה-IP ל-`runtime/login-blacklist.json`.
- יוצרת את `runtime/CRM_LOCKED` ונועלת את כל ה-CRM, כולל סשנים קיימים ו-API/MCP.
- משאירה את `/health` זמין כדי שתהליך ה-Node יישאר בריא אצל ספק האירוח.

לאחר בדיקה ידנית ב-Hostinger ניתן לפתוח את המערכת על-ידי מחיקת `runtime/CRM_LOCKED`. אם הניסיון היה שלך, יש להסיר ידנית גם את הרשומה המתאימה מתוך `runtime/login-blacklist.json`; אם לא, משאירים את ה-IP ברשימה השחורה. `LOGIN_MAX_ATTEMPTS` קובע את הסף, ו-`TRUST_PROXY=true` נדרש בפריסה מאחורי reverse proxy כדי ש-Fastify ישתמש ב-IP המקורי של המבקר.

שימו לב: נעילה גלובלית לאחר שלושה ניסיונות היא מדיניות מחמירה ומאפשרת לתוקף לגרום בכוונה לנעילת השירות; זהו trade-off מכוון של ההגדרה הזו.

## בדיקות ואבטחה

`npm run check` בודק תחביר בכל קובצי JavaScript והיעדר שרידי הארכיטקטורה הקודמת. `npm test` בודק הרשאות HTTP ו־MCP, כתיבה חלקית, זיהוי לקוחות, הודעות MIME בעברית, שיוך טיוטות והגנות נגד שליחה כפולה. בדיקות מסד משתמשות בכפילים מבוקרים; בדיקות ספקים חיות דורשות חיבור חשבונות אמיתיים.

`npm run scan:secrets` מבצע סריקה מקומית היוריסטית בלי להדפיס ערכי סודות. `npm audit` בודק תלויות. מוצמדת `sharp@0.35.4` באמצעות overrides כדי להסיר חולשות ספריית תמונה שנמשכת בעקיפין על ידי Transformers. נתיב ה־AI ביישום משתמש בטקסט בלבד.

יש לסרוק גם היסטוריית Git לפני פרסום המאגר. אין להעלות `.env`, מפתחות, sessions, אסימוני OAuth, קובצי מודל או נתוני לקוחות. מעבר מטבלאות של מערכת קיימת מחייב גיבוי ובדיקת התאמת המבנה; יצירת טבלאות חסרות אינה ממירה אוטומטית סכימה זרה או נתונים היסטוריים.

## יכולות העיבוד החכם

- תור הודעות עמיד במסד: ההודעה ועבודת העיבוד נכתבות באותה עסקה. תפיסה עם נעילה וזמן תפוגה, חידוש בעלות, ניסיונות חוזרים ומזהי פעולה ייחודיים.
- סיווג רגיל/ספאם/חשוד/אוטומטי/שיווקי/מערכת/לא ידוע באמצעות כללים וניתוח AI. משוב ידני לפי שולח, תיקיית ספאם נפרדת ותיעוד שינויים. מצב הצעה אינו מעביר ספאם אוטומטית.
- זיהוי לקוחות לפי אימייל וטלפון מנורמל, כולל זהויות חלופיות. התאמות עמומות דורשות טיפול ידני. יצירה מקבילה משתמשת בנעילה משותפת לכל נתיבי היצירה.
- הצעות פרויקט, משימה, חברה ותפקיד עם מקור מהודעה; שינויים בפרויקט קיים מאושרים בנפרד. משימות עם תאריך יוצרות תזכורת. חילוץ תאריכים בעברית משתמש ביום המקומי בישראל.
- הקשר מוגבל באורך עם דירוג רלוונטיות/עדכניות, מקורות, קבצים ותזכורות המשויכים ללקוח. מידע מפרויקטים משותפים אינו נכלל בטיוטה ללקוח. אין העתקת כל המסד לספק.
- כלי עוזר עם סכמות קשיחות, הרשאות, רישום ביקורת, אישור עם אסימון קצר־חיים ופרטי פעולה בלתי משתנים. כישלון שליחה לא ודאי אינו נשלח שוב אוטומטית.
- פרויקטים ומערכות: ארכוב, שחזור, מחיקה רכה ומחיקה קבועה מפורשת אחרי מחיקה רכה; קשרים נבדקים וניתוקם מחייב אישור נוסף.
- קבצים: העלאה עד 25MB; אינדוקס טקסט מוגבל ל־10MB, עד 100 עמודי PDF ו־200,000 תווי טקסט. תמיכה ב־TXT/MD/JSON/CSV/PDF/DOCX, ללא OCR. עריכה בקובצי טקסט בלבד. ארכיון, סל מחזור ושחזור; שינוי תיקייה הוא שינוי מטא־נתונים.
- מרכז התראות, תזכורות, יומן פעולות ומסכי מצב לתור ולאבטחה. בדיקות רכיבי PDF/Word נעשות בתהליך עבודה מוגבל בזמן ובזיכרון.

## מדיניות אוטומציה ושליחה

ברירת המחדל: הצעת לקוחות/פרויקטים/משימות, טיוטות אוטומטיות ואישור לכל שינוי בצ׳אט. מצבי האוטומציה נשמרים במסד ואינם דורשים פריסה מחדש.

`always_confirm` מבקש אישור לשינויים. `confirm_sensitive` מאפשר יצירת משימה/תזכורת/טיוטה ללא אישור נוסף. `never_auto_send` מחייב אישור לכל שליחה. `auto_send_trusted` מאפשר שליחה רק ללקוח שברשימה המפורשת וכשהמשתמש כתב בצ׳אט פקודת שליחה עם שם מדויק, ערוץ וטקסט במירכאות; הגוף והנמען חייבים להתאים בדיוק. ניסוח חופשי או מידע מתוך הודעת לקוח אינם אישור. שום עבודת רקע אינה שולחת הודעות חיצוניות.

## עדכוני מבנה ופריסה

הפעלת השרת יוצרת טבלאות חסרות ומוסיפה עמודות בלבד: `app_settings`, `ai_audit`, `ai_actions`, `client_identities`, `sender_feedback`, `ai_suggestions`, `reminders`, `file_content`, `knowledge_candidates`, `knowledge_articles`; הרחבות לתור, הודעות, טיוטות, לקוחות, קבצים, פרויקטים, מערכות ורישומי שליחה. קבצים ונתונים קיימים אינם נמחקים במיגרציה. יש לגבות את המסד ואת תיקיית הנתונים ולבדוק על עותק של מסד הפריסה לפני עדכון סביבת העבודה החיה.

מנגנון העיבוד פועל בתהליך השרת. נדרש מופע מתמשך אצל ספק האירוח; תהליך שאינו פועל לא יסנכרן ולא יריץ תזכורות. פעולות שכבר נכתבו לתור מתחדשות עם חזרת התהליך. פקודות בדיקה: `npm run check`, `npm test`, `npm run scan:secrets`, `npm audit`.

פירוט רכיבי הקוד הפתוח והרישיונות: [docs/components.md](docs/components.md). מצב אימות ומגבלות: [VALIDATION.md](VALIDATION.md).

## מעקבים וידע עסקי מאושר

מסך המעקבים מזהה משימות באיחור, הודעות נכנסות שממתינות לתשובה והודעות יוצאות ללא מענה. ברירת המחדל היא הצעה; אפשר ליצור תזכורת ידנית או להפעיל יצירה אוטומטית בהגדרות. סריקת הרקע מתוזמנת כל 15 דקות. זמני ההמתנה ניתנים לשינוי; תאריך משימה ללא שעה מסתיים בסוף יום UTC. ספאם ופרויקטים לא פעילים מוחרגים, ולכל מקור מעקב יש מזהה למניעת כפילויות. טיוטת מעקב נבדקת שוב לפני שמירה, ומבוטלת אם התקבלה הודעה חדשה או שהתזכורת בוטלה. שליחה דורשת אישור במסך השיחה.

מסך ידע עסקי מאפשר להפיק הצעת נוהל כללי מהודעה, לערוך, לאשר ולהעביר לארכיון. רק תוכן שעבר אישור מפורש נכלל בהקשר משותף. בדיקות מזהים מסייעות להרחיק פרטי לקוחות, אך בעל המערכת חייב לבדוק גם מחירים, הסכמים ופרטים מסחריים פרטיים לפני אישור. מקורות ההצעה נשמרים בנפרד ואינם מועברים כהקשר משותף.

פעולות התור ועובד המשימות משתמשים ברישום פעולות עמיד וביומן הביקורת המשותף. בעלות על עבודה נבדקת מול המסד לפני ביצוע ולפני השלמת הרישום; פעולות פנימיות אינן זמינות ככלי צ׳אט. פעולות התחום שומרות על עסקאות ומזהי מקור משלהן, משום שמסירת עבודות יכולה להתרחש יותר מפעם אחת. `DB_POOL_SIZE` מוגבל למינימום 6 חיבורים כדי לאפשר נעילות, עסקאות וחידוש בעלות במקביל.
